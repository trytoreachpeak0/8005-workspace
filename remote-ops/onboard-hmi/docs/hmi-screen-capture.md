# 远程看车载端屏上显示：调研与结论

[workspace#16](https://github.com/trytoreachpeak0/8005-workspace/issues/16)，2026-10-11。

## 为什么要做

现场真车票（例如 control-server#566）的会话只能经 SSH 读车载端日志、配置和服务端接口，
看不到操作员屏上显示什么。屏上的状态一直靠用户在现场拍照转述：10-10 晚「需人工充电：
服务端保持」时屏上没有按钮，就是用户截图发来才知道的。日志说的是「程序认为自己做了什么」，
屏说的是「操作员实际看到什么」，两者不一致时，后者才是要排查的东西。

障碍在 Windows 的会话隔离：sshd 是服务，SSH 进来的命令跑在 session 0；车载端
`SQCD.Agv.Wpf` 跑在 `HT` 的桌面会话（session 1）。在 session 0 里截屏，截到的是一个没人看的
空桌面。所以一切做法的前提，都是先把一段代码送进 session 1 去跑。

## 结论

**用甲＋乙，合成一个脚本：`scripts/17-capture-hmi-screen.ps1`。**一次运行同时拿到截屏 PNG、
每个车载端窗口单独的 PNG、以及 UI Automation 控件树与可见文字的 JSON。不改车载端，不动
操作员的屏。丙（车载端自己导出屏上状态）现在不需要，留作建议，见文末。

## 各做法比较

进 session 1 的办法四种做法共用：沿用 `10-start-onboard-stack.ps1` 与
`16-enter-sublot-uia.ps1` 的「在交互会话里登记一次性 Interactive 计划任务、跑完即注销」。
差别在进去之后做什么。

| | 甲：截屏 PNG | 乙：UIA 控件树 JSON | 丙：车载端自导出 | 丁：VNC 只看模式 |
| --- | --- | --- | --- | --- |
| 看得到什么 | 屏上全部像素，含别的程序的弹框、任务栏、系统通知 | 车载端每个窗口的控件：文字、按钮是否可用、勾选状态、输入框内容、哪个控件有焦点；**含隐藏窗口挂着的弹框** | 车载端自己认为的界面状态（视图模型），可带内部字段 | 实时画面，可连续看 |
| 看不到什么 | 被遮住的窗口；锁屏时只能看到锁屏或黑屏 | 自绘内容（图片、画布上画的东西）；别的程序的界面细节 | 屏上实际渲染出来的样子；车载端以外的弹框 | 留不下结构化记录 |
| 要不要改车载端 | 不要 | 不要 | **要**，单开车载端票 | 不要 |
| 对操作员有无干扰 | 无（只读像素） | 无（只读属性）；WPF 会为读取者建自动化对等对象，不改界面 | 无 | 有风险：VNC 会话能点能输，只看模式靠配置保证；连上时屏上可能出提示 |
| 锁屏时 | 截不到车载端（截到锁屏或黑屏） | 一般仍能读（cs#566 曾在锁屏下用 UIA 找到过输入框），以实测为准 | 照常 | 看到锁屏 |
| 熄屏时 | 通常仍截得到（合成器照常画）；截出纯色会报出来 | 照常 | 照常 | 视显示器而定 |
| 自动化程度 | 一条命令，结果入证据 | 同左 | 一条命令 | 要人看着 |

另外两个想过但不采用的：

- **只靠车载端日志推屏上状态**：就是现状，问题正在这里——日志与屏不一致的时候正是要看屏的时候。
- **在 session 0 里截屏**：截到的是服务桌面，什么都没有。

### 为什么甲和乙要一起取

两者互补，且共用同一次进 session 1：截屏是「人看到的」，回答「屏上有没有那个按钮」；
UIA 是「机器读得出的」，能 grep、能比对、能看隐藏窗口。车载端拒收配置时的弹框挂在隐藏窗口上
（工作区记忆 `onboard-config-rejected-silently`），只看截屏可能看见、只看主窗口的 UIA 一定看不见，
所以脚本把车载端进程的**全部**顶层窗口都列出来，可见与否都记，每个都读 UIA。

截屏也分两种取：全屏截图看整个桌面；`PrintWindow` 按窗口取，即使被别的窗口挡住也能取全。

## 「只读」是怎么保证的

票要求取屏脚本对屏幕没有任何写操作。脚本在三处把这件事钉住：

1. **不出窗口、不抢前台。**计划任务直接跑 `pwsh.exe` 会在操作员屏上弹一个控制台窗口并抢走
   前台。脚本改为让任务跑 `wscript.exe`，由一段 VBScript 以窗口样式 0（隐藏、不激活）启动
   pwsh。车端脚本在开头和结尾各记一次前台窗口；若前台属于取屏自己的进程，结果码是
   `FOCUS_DISTURBED`，那是本工具的缺陷。
2. **只调读的 API。**`-SelfTest` 逐字扫车端脚本，出现任何会动屏幕的调用名（`SetFocus`、
   `SetForegroundWindow`、`SendInput`、`InvokePattern`、`.SetValue(`、`Stop-Process` 等）就失败；
   并核对车端脚本导入的每个 Win32 函数都在一张只读清单上。
3. **不留残留。**计划任务起来 3 秒后在 `finally` 里注销；启动脚本删掉自己；取回后删掉车上的
   运行目录，再查一遍有没有 `W2G-CaptureHmi-*` 任务留着，结果写进运行记录。

密码框（UIA 的 `IsPassword`）不读值，并且在两种 PNG 上先涂黑再写盘。

## 结果码

脚本不重试，每次运行落在一个结果码上（括号里是退出码）：

| 结果码 | 含义 |
| --- | --- |
| `CAPTURED` (0) | 截屏、窗口图、UIA 文字都有 |
| `HMI_NOT_RUNNING` (2) | console 会话里没有车载端；桌面照样截了 |
| `DESKTOP_LOCKED` (3) | 锁屏；能读到的都留下（UIA 一般能读） |
| `SCREEN_BLANK` (4) | 截图是纯色，可能熄屏或截屏被拦 |
| `NO_INTERACTIVE_SESSION` (5) | console 没人登录，什么都没启动 |
| `TIMEOUT` (6) | `-TimeoutSeconds`（默认 90）内没出结果 |
| `PARTIAL` (7) | 跑了，但缺图或 UIA 为空，看 JSON 里的 `errors` |
| `FOCUS_DISTURBED` (8) | 取屏自己占了前台，是本工具的缺陷 |
| `WSH_DISABLED` (9) | Windows Script Host 被禁用（那时 wscript 会弹框），什么都没启动 |
| `DESKTOP_BUSY` (10) | 条码自动录入（`16-enter-sublot-uia`）的任务或进程正在跑，什么都没启动 |
| 工具失败 (1) | SSH、scp 或启动失败 |

## 离线验证（本机，2026-10-11）

- `-SelfTest` 26 项全过：两个脚本解析 0 错误、无控制字符、只读扫描、只读 Win32 清单、
  `agv01` 在参数校验时就被拒绝、生成的启动脚本与预检脚本解析 0 错误、启动脚本在 `finally` 里
  注销任务、VBScript 用窗口样式 0 且为纯 ASCII、各结果码的判定。自检还真抓到过一个 VBScript
  引号转义错误。
- 本机起了一个模仿车载端的 WPF 窗口（中文标题、站点文字、条码框、密码框、按钮、勾选框，
  外加一个**挂在隐藏窗口上**的配置错误弹框），走完整的「一次性计划任务 → wscript 隐藏 →
  车端脚本」路径：全屏图、两个窗口图（主窗口与弹框）、UIA 文字全部取到，可见文字依次是
  「假车载端 W2G｜需人工充电：服务端保持｜当前站点 N1-15_N1-16｜W2-1010-A2-1｜手动提交｜
  维护模式｜车载端｜OK｜配置校验失败：messageTimeoutMs 必须小于 3000」；密码框在图上是黑块、
  JSON 里没有密码原文；开始与结束时前台都是同一个窗口；任务与启动脚本无残留。
- 本机测试中有一次隐藏的 pwsh 停在 3 MB、零 CPU 超过一分钟没动，之后同样的路径与单独的
  wscript、`conhost --headless` 在计划任务里各试一次都正常，未能复现，原因未查明。这正是
  `TIMEOUT` 结果码存在的理由：卡住时脚本按时放弃并清理，不会挂住。
- 本机是远程桌面会话，没有 Active 的 console 会话，启动脚本如实拒绝（`No active console
  session`），顺带验证了那条路径。

## 不和条码自动录入同时跑

`16-enter-sublot-uia.ps1` 也是经交互计划任务进同一个桌面，而且它会往界面里写。调度定的规矩是
两个交互工具不同时跑（2026-10-11）。这条写进了预检：车上有 `W2G-EnterSublot-*` 任务，或有命令行
含 `agv-enter-sublot-uia` 的 pwsh 进程，就报 `DESKTOP_BUSY` 不启动。第一次实车取屏时这条还没进
脚本，是人工查的，那次只核到了任务、没核到进程（查询语句写错没执行），证据里照实记了。
加进脚本后本机做过正反对照：没有录入进程时报空，起一个命令行带该名字的进程后能看见。

## 实车验证

证据在 [`../evidence/ws16-20261011/`](../evidence/ws16-20261011/)，说明见其中的 `SUMMARY.md`。

**第一次：agv02，车载端栈运行，车静止，2026-10-11 12:37:56（控制端时刻）。**结果码 `CAPTURED`，
约 40 秒。屏上是 N1-4 站「需要恢复：DEPARTURE_UNSAFE」，发车安全「禁止发车」，行程计划停在
「N1-4 已到达、关卡待前往」。当时调度以为车已在 12:35:51 出发去关卡，截图说明车载端认为自己
还在站上要求恢复——取屏第一次用就揭出了一个状态不一致；调度随后确认车确实停在 N1-4，截屏是对的。
**用户在车边对照过这张截屏：「一样的，只是几分钟之前的画面」**（用户在调度窗口确认、调度转达）。取屏前后前台都是
车载端主窗口；车上运行目录已删，无残留任务。

读到的两个细节，记下来给以后看的人：

- 清单与行程计划的行，UIA 名字是数据对象的 `ToString()`（如 `WorklistItemRow { DemandId = …,
  Sublot = W2-1011-C-YI, … }`），因为车载端没给这些行设自动化名字。信息比屏上还全，但读起来乱；
  按 `Sublot =`、`StateText =` 这类字段找即可。
- 屏上「操作记录」的时间显示为 04:15，比北京时间慢 8 小时，看来车载端在那里显示的是 UTC。
  不属本票，调度已开 [8005-agv-onboard-hmi#304](https://github.com/trytoreachpeak0/8005-agv-onboard-hmi/issues/304)。

**第二次：锁屏。**（待做，按调度安排由现场的人按 Win+L。）
## 局限与剩余风险

- **锁屏时截不到车载端画面**，这是 Windows 的设计：锁屏时输入桌面换成 Winlogon 的安全桌面，
  用户会话里的程序截不到。UIA 读控件树不依赖输入桌面，一般仍可读。`HT` 是空密码账户，锁屏后
  在车上点一下「登录」即可回来，但那要人到车前。
- **自绘内容读不出文字**：车载端若把状态画成图片或画布，UIA 只看得到一个空控件，要看截屏。
- **熄屏判断不精确**：显示器关了时截屏通常照样有内容，脚本只能在截出纯色时报 `SCREEN_BLANK`，
  不能断言显示器亮不亮。
- **依赖 Windows Script Host**：被禁用时脚本拒绝启动（`WSH_DISABLED`），不会让 wscript 在操作员
  屏上弹错误框。若哪天车上禁了 WSH，替代是任务直接跑 `conhost.exe --headless pwsh.exe`，本机在
  计划任务里试过可行，未在车上试过。
- **完整性等级**：车载端若以管理员（高完整性）身份运行，`PrintWindow` 会被拒，结果码为 `PARTIAL`。
  经 10 号脚本启动的车载端与取屏任务同为普通完整性，不受影响。

## 给车载端的建议（丙，交调度决定是否开票）

现在不需要。若以后要在不进桌面会话的情况下读屏上状态（例如锁屏下也要稳定读到按钮是否
出现），可以请车载端在日志簿或一个只读本地文件里，每次主界面状态变化时写一行「屏上状态
快照」：当前页面、横幅文字、可按的按钮列表与可用状态。那属于 `8005-agv-onboard-hmi` 的改动，
本票不做。
