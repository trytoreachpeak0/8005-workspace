# 远程看车载端屏上显示：调研与结论

[workspace#16](https://github.com/trytoreachpeak0/8005-workspace/issues/16)，2026-10-11。

## 为什么要做

现场真车票（例如 control-server#566）的会话只能经 SSH 读车载端日志、配置和服务端接口，
看不到操作员屏上显示什么。屏上的状态一直靠用户在现场拍照转述：10-10 晚「需人工充电：
服务端保持」时屏上没有按钮，就是用户截图发来才知道的。日志说的是「程序认为自己做了什么」，
屏说的是「操作员实际看到什么」，两者不一致时，后者才是要排查的东西。

障碍在 Windows 的会话隔离：sshd 是服务，SSH 进来的命令跑在 session 0；车载端
`SQCD.Agv.Wpf` 跑在 `HT` 的桌面会话（session 1）。在 session 0 里截屏，截到的是一个没人看的
空桌面。所以一切做法的前提，都是先把一段代码送进 session 1 去跑。

## 结论

**用甲＋乙，合成一个脚本：`scripts/17-capture-hmi-screen.ps1`。**一次运行同时拿到截屏 PNG、
每个车载端窗口单独的 PNG、以及 UI Automation 控件树与可见文字的 JSON。不改车载端，不动
操作员的屏。丙（车载端自己导出屏上状态）现在不需要，留作建议，见文末。

## 各做法比较

进 session 1 的办法四种做法共用：沿用 `10-start-onboard-stack.ps1` 与
`16-enter-sublot-uia.ps1` 的「在交互会话里登记一次性 Interactive 计划任务、跑完即注销」。
差别在进去之后做什么。

| | 甲：截屏 PNG | 乙：UIA 控件树 JSON | 丙：车载端自导出 | 丁：VNC 只看模式 |
| --- | --- | --- | --- | --- |
| 看得到什么 | 屏上全部像素，含别的程序的弹框、任务栏、系统通知 | 车载端每个窗口的控件：文字、按钮是否可用、勾选状态、输入框内容、哪个控件有焦点；**含隐藏窗口挂着的弹框** | 车载端自己认为的界面状态（视图模型），可带内部字段 | 实时画面，可连续看 |
| 看不到什么 | 全屏图看不到被遮住的窗口（窗口图能）；锁屏时全屏图只有锁屏画面 | 自绘内容（图片、画布上画的东西）；别的程序的界面细节 | 屏上实际渲染出来的样子；车载端以外的弹框 | 留不下结构化记录 |
| 要不要改车载端 | 不要 | 不要 | **要**，单开车载端票 | 不要 |
| 对操作员有无干扰 | 无（只读像素） | 无（只读属性）；WPF 会为读取者建自动化对等对象，不改界面 | 无 | 有风险：VNC 会话能点能输，只看模式靠配置保证；连上时屏上可能出提示 |
| 锁屏时（agv02 实测） | 全屏图是锁屏画面；**按窗口取的图仍是完整的车载端界面** | **照常能读**，106 个节点 | 照常 | 看到锁屏 |
| 熄屏时（推断，未实测） | 应该仍截得到（合成器照常画）；截出纯色会报出来 | 照常 | 照常 | 视显示器而定 |
| 自动化程度 | 一条命令，结果入证据 | 同左 | 一条命令 | 要人看着 |

另外两个想过但不采用的：

- **只靠车载端日志推屏上状态**：就是现状，问题正在这里——日志与屏不一致的时候正是要看屏的时候。
- **在 session 0 里截屏**：截到的是服务桌面，什么都没有。

### 为什么甲和乙要一起取

两者互补，且共用同一次进 session 1：截屏是「人看到的」，回答「屏上有没有那个按钮」；
UIA 是「机器读得出的」，能 grep、能比对、能看隐藏窗口。车载端拒收配置时的弹框挂在隐藏窗口上
（工作区记忆 `onboard-config-rejected-silently`），只看截屏可能看见、只看主窗口的 UIA 一定看不见，
所以脚本把车载端进程的**全部**顶层窗口都列出来，可见与否都记，每个都读 UIA。

截屏也分两种取：全屏截图看整个桌面；`PrintWindow` 按窗口取，即使被别的窗口挡住也能取全。

## 「只读」是怎么保证的

票要求取屏脚本对屏幕没有任何写操作。脚本在三处把这件事钉住：

1. **不出窗口、不抢前台。**计划任务直接跑 `pwsh.exe` 会在操作员屏上弹一个控制台窗口并抢走
   前台。脚本改为让任务跑 `wscript.exe`，由一段 VBScript 以窗口样式 0（隐藏、不激活）启动
   pwsh。车端脚本在开头和结尾各记一次前台窗口；若前台属于取屏自己的进程，结果码是
   `FOCUS_DISTURBED`，那是本工具的缺陷。
2. **只调读的 API。**`-SelfTest` 逐字扫车端脚本，出现黑名单上任何会动屏幕的调用名（`SetFocus`、
   `SetForegroundWindow`、`SetWindowPos`、`SendInput`、`InvokePattern`、`ScrollIntoView`、
   `DoDefaultAction`、`.SetValue(`、`Stop-Process` 等）就失败；并核对车端脚本导入的每个 Win32 函数
   都在一张只读清单上。**这是有边界的黑名单**：只认得直接写出来的名字，运行时拼出来的名字、经反射
   调用的方法认不出来。更强的做法是按语法树做白名单，本票没做，记在剩余风险里。
3. **收尾，并把残留列出来。**计划任务起来 3 秒后在 `finally` 里注销；启动脚本删掉自己；取回后删掉
   车上的运行目录，再查一遍还有没有 `W2G-CaptureHmi-*` 任务、有没有取屏相关的 pwsh 或 wscript 进程，
   写进运行记录的 `leftoverTasksAfter` 与 `leftoverProcessesAfter`。脚本**不停任何进程**，所以车上
   取屏卡住时进程会留着，只是被列出来。能保证的是**控制端不挂住**：最多等 `-TimeoutSeconds` 加几次
   SSH 往返就给出结果码。

密码框（UIA 的 `IsPassword`）不读值，并且在两种 PNG 上先涂黑再写盘。

## 结果码

脚本不重试，每次运行落在一个结果码上（括号里是退出码）：

| 结果码 | 含义 |
| --- | --- |
| `CAPTURED` (0) | 截屏、窗口图、UIA 文字都有 |
| `HMI_NOT_RUNNING` (2) | console 会话里没有车载端；桌面照样截了 |
| `DESKTOP_LOCKED` (3) | 锁屏；全屏图是锁屏画面，车载端窗口图与 UIA 文字照常（agv02 实测） |
| `SCREEN_BLANK` (4) | 截图是纯色，可能熄屏或截屏被拦 |
| `NO_INTERACTIVE_SESSION` (5) | console 没人登录，什么都没启动 |
| `TIMEOUT` (6) | 已启动，但 `-TimeoutSeconds`（默认 90）内没出结果；运行记录的 `startedMarker` 说明车端脚本有没有跑起来 |
| `PARTIAL` (7) | 跑了，但缺图或 UIA 为空，看 JSON 里的 `errors` |
| `FOCUS_DISTURBED` (8) | 取屏自己占了前台，是本工具的缺陷 |
| `WSH_DISABLED` (9) | Windows Script Host 被禁用（那时 wscript 会弹框），什么都没启动 |
| `DESKTOP_BUSY` (10) | 条码自动录入（`16-enter-sublot-uia`）的任务或进程正在跑，什么都没启动 |
| `TOOL_FAILURE` (1) | SSH、scp 失败，或启动没证明任务起来、车端脚本也没跑起来 |

### 启动成没成，结果文件说了算

启动脚本 3 秒后读一次任务状态（`lastTaskResult`）。判定规则与 16 号脚本一致（8005-workspace#20）：
任务计划程序自己的状态码（就绪、禁用、尚未运行、排队等，即 `0x41300`～`0x41325` 中除运行中 `0x41301`
以外的几个）和 `0x8004`、`0x8007` 开头的启动失败码，算没起来；其余都算起来了，包括已经结束的
`0x0`、`0x1`、`0xC000013A`。即使判为没起来，也先查一次结果文件，有就取回；收尾删目录前同样先查。
车端脚本第一件事是写 `<名字>.started`。没有结果时用它区分「从没跑起来」（`TOOL_FAILURE`，启动已证明
时为 `TIMEOUT`）和「跑了但卡住」（`TIMEOUT`，并列出残留进程）。

### 怎么判锁屏

三个信号，任一个成立就算锁屏，三个都记进 `desktop.lockSignals`：输入桌面不是 `Default`（例如弹出了
登录框）；会话里有 `LogonUI` 进程；前台进程是 `LockApp`（Windows 10 的锁屏画面）。agv02 那次锁屏，
第一个信号没成立，后两个成立。

## 离线验证（本机，2026-10-11）

- 审查修订后 `-SelfTest` 51 项全过；对新增的检查做了 22 个变异，21 个被自检打死（见下）。
  最初版本 26 项全过：两个脚本解析 0 错误、无控制字符、只读扫描、只读 Win32 清单、
  `agv01` 在参数校验时就被拒绝、生成的启动脚本与预检脚本解析 0 错误、启动脚本在 `finally` 里
  注销任务、VBScript 用窗口样式 0 且为纯 ASCII、各结果码的判定。自检还真抓到过一个 VBScript
  引号转义错误。
- 本机起了一个模仿车载端的 WPF 窗口（中文标题、站点文字、条码框、密码框、按钮、勾选框，
  外加一个**挂在隐藏窗口上**的配置错误弹框），走完整的「一次性计划任务 → wscript 隐藏 →
  车端脚本」路径：全屏图、两个窗口图（主窗口与弹框）、UIA 文字全部取到，可见文字依次是
  「假车载端 W2G｜需人工充电：服务端保持｜当前站点 N1-15_N1-16｜W2-1010-A2-1｜手动提交｜
  维护模式｜车载端｜OK｜配置校验失败：messageTimeoutMs 必须小于 3000」；密码框在图上是黑块、
  JSON 里没有密码原文；开始与结束时前台都是同一个窗口；任务与启动脚本无残留。
- 本机测试中有一次隐藏的 pwsh 停在 3 MB、零 CPU 超过一分钟没动，之后同样的路径与单独的
  wscript、`conhost --headless` 在计划任务里各试一次都正常，未能复现，原因未查明。这正是
  `TIMEOUT` 结果码存在的理由：车上卡住时控制端按时放弃并清理，不跟着挂住。
- 本机是远程桌面会话，没有 Active 的 console 会话，启动脚本如实拒绝（`No active console
  session`），顺带验证了那条路径。
- 审查修订后，用两个本地函数替掉 `ssh` 和 `scp`、把 console 会话匹配换成远程桌面会话，在本机走完整
  控制端流程两遍。正常一遍得 `HMI_NOT_RUNNING`（本机没有车载端），三处时钟计数都在，运行目录删净。
  另一遍把车端脚本改成写完开始标记后睡 30 秒、超时设 8 秒：得 `TIMEOUT`（退出码 6），控制端 22 秒
  结束，`startedMarker` 读到，`leftoverProcessesAfter` 列出还在跑的 wscript 与 pwsh，目录因被占用报
  `RUN_DIRECTORY_LEFT`。这验证的是控制端流程，SSH 与车上环境不在其中。
- 变异：改坏启动判定（去掉 `8004`/`8007`、`0x41303`、`0x41325`）、无结果判定的两个分支、收尾时取回与
  删除的先后、退出码表缺键或重码、判锁屏的三个信号、导入扫描的正则、黑名单新增的五个名字、对 16 号的
  两个匹配模式、16 号改掉任务名、启动行去掉时钟计数，都被打死。**存活一个**：把收尾时「先取回结果」
  那一步的条件改成恒假。自检只按语法树检查了先后顺序，这一步是否真的执行离线测不到，只有上面的
  本机全流程跑到过它的正常分支。

## 不和条码自动录入同时跑

`16-enter-sublot-uia.ps1` 也是经交互计划任务进同一个桌面，而且它会往界面里写。调度定的规矩是
两个交互工具不同时跑（2026-10-11）。这条写进了预检：车上有 `W2G-EnterSublot-*` 任务，或有命令行
含 `agv-enter-sublot-uia` 的 pwsh 进程，就报 `DESKTOP_BUSY` 不启动。第一次实车取屏时这条还没进
脚本，是人工查的，那次只核到了任务、没核到进程（查询语句写错没执行），证据里照实记了。
加进脚本后本机做过正反对照（本机实测，车上未实测）：没有录入进程时报空，起一个命令行带该名字的进程后能看见。
`-SelfTest` 还会从 16 号脚本的语法树里取出它生成启动脚本的函数并调用，断言它登记的任务名与 pwsh 命令行
都能被这两个匹配模式认出，16 号改名时自检会红。

## 实车验证

证据在 [`../evidence/ws16-20261011/`](../evidence/ws16-20261011/)，说明见其中的 `SUMMARY.md`。

**第一次：agv02，车载端栈运行，车静止，2026-10-11 12:37:56（控制端时刻）。**结果码 `CAPTURED`，
约 40 秒。屏上是 N1-4 站「需要恢复：DEPARTURE_UNSAFE」，发车安全「禁止发车」，行程计划停在
「N1-4 已到达、关卡待前往」。当时调度以为车已在 12:35:51 出发去关卡，截图说明车载端认为自己
还在站上要求恢复——取屏第一次用就揭出了一个状态不一致；调度随后确认车确实停在 N1-4，截屏是对的。
**用户在车边对照过这张截屏：「一样的，只是几分钟之前的画面」**（用户在调度窗口确认、调度转达）。取屏前后前台都是
车载端主窗口；车上运行目录已删，无残留任务。

读到的两个细节，记下来给以后看的人：

- 清单与行程计划的行，UIA 名字是数据对象的 `ToString()`（如 `WorklistItemRow { DemandId = …,
  Sublot = W2-1011-C-YI, … }`），因为车载端没给这些行设自动化名字。信息比屏上还全，但读起来乱；
  按 `Sublot =`、`StateText =` 这类字段找即可。
- 屏上「操作记录」的时间显示为 04:15，比北京时间慢 8 小时，看来车载端在那里显示的是 UTC。
  不属本票，调度已开 [8005-agv-onboard-hmi#304](https://github.com/trytoreachpeak0/8005-agv-onboard-hmi/issues/304)。

**第二次：锁屏，agv02，2026-10-11 20:04:19（控制端时刻）。**由 cs#566 现场会话在两车静止于等待点、
没有在途单时代跑（脚本为本分支 `b55d108`，在它自己的 detached worktree 里运行），用户在车上按 Win+L、
确认锁屏后取，取完解锁。结果码 `DESKTOP_LOCKED`（预期），预检与车端都判为锁屏（`logonUi=true`）。

| 取到的东西 | 实测 |
| --- | --- |
| 全屏图 | 锁屏画面（风景图与 20:04 时钟），没有车载端 |
| 车载端窗口图（`PrintWindow`） | **完整的车载端界面**：上层会话就绪、在等待点3 待命、允许发车、8 个仓已锁空仓 |
| UIA 文字 | 106 个节点，车载端文字齐全 |
| 前台窗口 | 前后都是 `LockApp`（锁屏程序），取屏没有动它 |
| 收尾 | 车上运行目录已删，无残留任务 |

这推翻了取屏前的两个预期，照实改正：

- **锁屏时并非什么都截不到。**Windows 10 的锁屏画面（`LockApp`）就画在用户自己的桌面上，所以全屏图
  截到的是锁屏画面而不是黑屏；车载端窗口被它盖住，但 `PrintWindow` 向合成器要的是窗口自己的画面，
  不受遮挡，照样完整。弹出输入密码的登录框时应会换到 Winlogon 安全桌面（推断，未实测）；`HT` 空密码，这次没出现。
- **「输入桌面名不是 Default」不能用来判断锁屏。**锁屏时读到的仍是 `Default`；这次认出锁屏靠的是
  会话里有 `LogonUI` 进程（前台也是 `LockApp`）。脚本取「或」，所以判对了。审查后判锁屏抽成纯函数，
  加了第三个信号 `LockApp`，每个信号各有用例。

要注意的是窗口图与 UIA 读到的是「解锁后操作员会看到的界面」，而锁屏期间操作员眼前是锁屏画面。
`DESKTOP_LOCKED` 这个结果码就是用来提醒这一点的。

## 局限与剩余风险

- **锁屏时全屏图只有锁屏画面**，车载端界面要看窗口图和 UIA 文字（agv02 实测两者都完整）。若锁屏后
  出现了登录框（换到 Winlogon 安全桌面），情况可能不同，未实测。`HT` 是空密码账户，锁屏后在车上点一下
  「登录」即可回来，但那要人到车前。
- **自绘内容读不出文字**：车载端若把状态画成图片或画布，UIA 只看得到一个空控件，要看截屏。
- **熄屏判断不精确**：显示器关了时截屏通常照样有内容，脚本只能在截出纯色时报 `SCREEN_BLANK`，
  不能断言显示器亮不亮。
- **依赖 Windows Script Host**：被禁用时脚本拒绝启动（`WSH_DISABLED`），不会让 wscript 在操作员
  屏上弹错误框。若哪天车上禁了 WSH，替代是任务直接跑 `conhost.exe --headless pwsh.exe`，本机在
  计划任务里试过可行，未在车上试过。
- **完整性等级（推断）**：本机有一次 `PrintWindow` 被一个以管理员身份运行的程序（Core Temp）拒绝，
  原因推断为完整性等级不同，没有单独验证。按这个推断，车载端若以管理员身份运行，结果码会是 `PARTIAL`；
  经 10 号脚本启动的车载端与取屏任务同为普通完整性，实车两次都取到了窗口图。
- **只读检查是有边界的黑名单**：认不出运行时拼出的名字、反射调用。按语法树做白名单更强，本票没做。
- **收尾时取回结果那一步只做了结构检查**：变异测试里唯一存活的一个就在这里（见离线验证）。
- **16 号没有对称检查**：17 号的自检会在 16 号改名时变红，反过来 16 号改动时不会跑 17 号的自检。
  在 16 号里加对称检查不在本票范围。
- **DPI**：车端请求「按显示器感知 DPI」在 agv02 上返回失败（`dpiAware=false`，pwsh 已经设过自己的
